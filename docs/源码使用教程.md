# 源码使用教程

## 1. 环境要求

建议环境：

- Python 3.10 或更高版本
- pip
- Nginx
- 一台普通 Linux 服务器

本教程使用 Python 虚拟环境部署。

## 2. 上传源码

把源码目录上传到服务器，例如：

```bash
/opt/relay-site
```

进入项目后端目录：

```bash
cd /opt/relay-site/site_app
```

## 3. 安装依赖

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 4. 设置后台账号密码

启动前建议设置环境变量：

```bash
export SITE_ADMIN_USER="fyanxv"
export SITE_ADMIN_PASSWORD="请改成强密码"
export SITE_DB_PATH="/opt/relay-site/site_app/data/site.db"
export SITE_DOWNLOAD_DIR="/opt/relay-site/site_app/data/downloads"
```

## 5. 测试启动

```bash
uvicorn app:app --host 127.0.0.1 --port 8000
```

浏览器访问：

```text
http://服务器IP:8000/
http://服务器IP:8000/fyanxv
```

确认能打开后，按 `Ctrl + C` 停止测试服务。

## 6. 使用 systemd 常驻运行

创建服务文件：

```bash
nano /etc/systemd/system/relay-site.service
```

写入：

```ini
[Unit]
Description=Relay Site
After=network.target

[Service]
WorkingDirectory=/opt/relay-site/site_app
Environment=SITE_ADMIN_USER=fyanxv
Environment=SITE_ADMIN_PASSWORD=请改成强密码
Environment=SITE_DB_PATH=/opt/relay-site/site_app/data/site.db
Environment=SITE_DOWNLOAD_DIR=/opt/relay-site/site_app/data/downloads
ExecStart=/opt/relay-site/site_app/.venv/bin/uvicorn app:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

启动服务：

```bash
systemctl daemon-reload
systemctl enable relay-site
systemctl start relay-site
systemctl status relay-site
```

查看日志：

```bash
journalctl -u relay-site -f
```

## 7. 配置 Nginx

示例配置：

```nginx
server {
    listen 80;
    server_name 你的域名;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

保存后重载：

```bash
nginx -t
systemctl reload nginx
```

如果使用 HTTPS，可以用你熟悉的证书工具申请证书后再把域名反向代理到 `127.0.0.1:8000`。

## 8. 后台初始化

访问：

```text
https://你的域名/fyanxv
```

后台可以配置：

- 品牌名
- 站点域名文案
- 首页公告
- 购买卡密地址
- Claude 显示名称和 API 地址
- Codex 显示名称和 API 地址
- 余额查询接口
- 模型统计接口
- 24 小时用量接口
- Windows / macOS / Linux 安装包

## 9. 网站功能说明

### 首页

首页提供卡密输入和一键导入能力。用户输入卡密后，可以选择导入 Claude 或 Codex。页面会生成 `ccswitch://` 导入链接，唤起本机 CC-Switch 并写入 provider 配置。

### 余额查询页

余额页会请求后台配置的余额接口，并展示：

- 卡密状态
- 套餐名称
- 计费类型
- 剩余额度
- 已用额度
- 总额度
- 到期时间
- 24 小时请求数和 Token 用量
- 模型用量排行

### 状态页

状态页用于展示通道可用性、延迟、成功率等状态信息。你可以接入自己的状态接口，也可以按现有结构调整。

### 教程页

教程页指导用户：

- 安装 Node.js
- 安装 Git
- 下载并安装 CC-Switch
- 从首页导入通道
- 安装 Claude Code CLI
- 安装 Codex CLI
- 在终端或 VS Code 中使用

### 后台

后台用于管理站点配置和下载包。下载包按平台区分：

- Windows
- macOS
- Linux

用户访问首页或教程页时，会优先显示适合当前系统的安装包。

## 10. 余额接口字段参考

余额接口建议返回 JSON。项目兼容以下常见字段：

```json
{
  "key_preview": "ABCD****WXYZ",
  "status": "active",
  "service_type": "claude",
  "sub_service_type_name": "套餐名称",
  "billing_type": "quota",
  "quota": {
    "type": "quota",
    "total_quota": 10000,
    "remaining_quota": 8000,
    "used_quota": 2000,
    "used_percent": 20
  },
  "usage": {
    "request_count": 10,
    "total_tokens": 100000
  },
  "timestamps": {
    "expires_at": "2026-12-31T00:00:00.000Z"
  }
}
```

时长型卡密可以使用：

```json
{
  "billing_type": "duration",
  "quota": {
    "daily_quota": 10000,
    "daily_remaining": 7000,
    "daily_spent": 3000,
    "daily_used": 30,
    "next_reset_at": "2026-12-31T16:00:00.000Z"
  }
}
```

## 11. 常见问题

### 后台打不开

检查服务是否运行：

```bash
systemctl status relay-site
```

检查日志：

```bash
journalctl -u relay-site -n 100
```

### 下载包上传后前台没变化

先确认后台是否已经启用对应平台的安装包，然后让浏览器强制刷新页面。

### 余额查询偶尔失败

后端已经对上游查询做了短重试。如果仍然失败，通常是上游接口临时繁忙或网络抖动，可以稍后重试。
